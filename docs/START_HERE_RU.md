# SYNCO: как собрать приложение с Claude Code

Порядок такой: сначала подготовка один раз, потом этапы по очереди. Каждый этап — один промпт: копируете его в Claude Code, ждёте результата, проверяете и только потом идёте дальше.

---

## 0. Подготовка (один раз, около 40 минут)

**Аккаунты (все бесплатные на старте):**
1. **GitHub** — github.com. Создайте пустой репозиторий `synco` (private).
2. **Supabase** — supabase.com. New project, регион **Frankfurt (eu-central-1)**: так данные будут храниться в EU. Сохраните пароль базы.
3. **Vercel** — vercel.com, вход через GitHub.
4. **Anthropic Console** — console.anthropic.com. Создайте API key и пополните баланс на $10–20, этого хватит на разработку.
5. **Google Cloud Console** — понадобится на этапе 1 для входа через Google и на этапе 5 для Drive. Claude Code подскажет, какие кнопки нажимать.

**Программы на компьютере:**
1. **Node.js LTS** — nodejs.org.
2. **Git** — git-scm.com.
3. **Claude Code**: в терминале выполните `npm install -g @anthropic-ai/claude-code`. Нужна подписка Claude Pro или Max.
4. Создайте папку проекта, например `~/synco`, и откройте в ней терминал.
5. Положите в эту папку подпапку `docs` с содержимым этого пакета (все .md файлы и папку `design`). Файл `CLAUDE.md` положите в корень `~/synco`.
6. Запустите `claude`.

> Совет: в начале каждой сессии пишите «Прочитай CLAUDE.md и docs/PROGRESS.md». Если что-то сломалось, вставьте текст ошибки и попросите исправить. Не переходите к следующему этапу, пока текущий не работает.

## Этап 1 — Каркас, вход, онбординг, орг-дерево (≈1 неделя)

```
Прочитай CLAUDE.md и все файлы в docs/. Мы начинаем Этап 1.
1) Создай проект Next.js 15 + TypeScript + Tailwind + shadcn/ui, перенеси дизайн-токены из docs/README.md в tailwind.config.
2) Подключи Supabase (я дам URL и ключи — спроси их), создай миграции для workspaces, profiles, memberships, departments, permissions, join_requests с RLS, и seed с демо-данными REGAGRO.
3) Сделай экраны по прототипу docs/design/SYNCO Auth.dc.html: вход (email+пароль и Google), регистрация (создать пространство / запросить доступ), восстановление пароля, принятие приглашения. После входа — редирект по роли.
4) Онбординг владельца и сотрудника по docs/design/SYNCO Onboarding.dc.html.
5) Редактор орг-дерева по docs/design/SYNCO Org Editor.dc.html и Настройки → Профиль, Пространство, Участники и роли, Права.
6) Общая шапка с вкладками и переключатель EN/RU (next-intl, русский словарь возьми из docs/design/i18n.js).
Покажи, как запустить локально, и создай docs/PROGRESS.md.
```
**Проверка:** можно зарегистрироваться, создать REGAGRO, добавить отделы, пригласить человека, войти под ним и переключить язык.

**Деплой:** попросите «Подключи проект к GitHub и Vercel, объясни по шагам». После этого у вас будет живая ссылка.

## Этап 2 — Цели, задачи, нить, результаты, проверка (≈2 недели)

```
Этап 2. Прочитай docs/SPEC_WORKFLOWS.md.
1) Миграции: goals, tasks, task_results, task_comments, reviews, task_events + RPC-функции для смены стадий строго по SPEC_WORKFLOWS (результат обязателен для "готово").
2) Моё пространство сотрудника по docs/design/SYNCO Workspace.dc.html: нить, полосы, анимация падения, карточка задачи с полем «Результат» (документ/ссылка/изображение → Supabase Storage), комментарии.
3) Поток работ владельца по docs/design/SYNCO Flow.dc.html: колонки отделов, карточка проверяющего, панель задачи с цепочкой проверки, очередь проверки с «Одобрить» и «Вернуть с комментарием» (статус «На доработку»). Панель закрывается полностью.
4) Ручное распределение по docs/design/SYNCO Assign.dc.html (выпадающий список с × и закрытием по клику снаружи + drag-and-drop), батарея и эффективность по формулам из SPEC_WORKFLOWS.
5) Realtime: изменения стадий видны всем без перезагрузки.
```
**Проверка:** владелец ставит задачу → тимлид передаёт её Тому → Том берёт её сегодня, прикрепляет файл и сдаёт → Джейн возвращает задачу с комментарием → Том исправляет → Джейн одобряет.

## Этап 3 — AI: декомпозиция и подбор исполнителей (≈1 неделя)

```
Этап 3. Прочитай docs/SPEC_AI.md.
1) Серверный модуль Claude API (ключ спроси у меня, храни в env на сервере).
2) Экран Цели → «Новая цель» по docs/design/SYNCO Goals.dc.html: декомпозиция с анимацией ниточек, подтверждение «Создать цель и пазл».
3) «✦ Предложить назначения» и «Одобрить все» на экране распределения — сначала детерминированный подбор по загрузке, предупреждение о перегрузке.
4) Пазл целей (соты) с состояниями деталей и анимацией.
```
**После этого этапа есть MVP.** Его можно показывать первым 2–3 командам.

## Этап 4 — Запросы, двухэтапная проверка, уведомления, дашборды ролей (≈1 неделя)

```
Этап 4.
1) requests + панель запросов во Потоке работ (обычные / приоритетные только для C-Level, принять / отклонить с причиной), бейджи источника на карточках, финальный проверяющий.
2) Дашборды C-Level и Team Lead по docs/design/SYNCO Roles.dc.html.
3) notifications + notification_prefs: центр уведомлений по docs/design/SYNCO Notifications.dc.html, колокольчик со счётчиком, email через Resend, Настройки → Уведомления.
4) Фильтр по целям в Потоке работ.
```

## Этап 5 — Синк и Google Drive (≈1–2 недели)

```
Этап 5. Прочитай раздел Sync Mind в docs/SPEC_AI.md.
1) pgvector, kb_documents, kb_chunks; индексация одобренных результатов (извлечение текста из PDF/DOCX/XLSX/PPTX, подписи к изображениям).
2) Панель Синка: запрос → подборка документов с кратким резюме → экспорт.
3) Интеграция Google Drive: OAuth в Настройках → Интеграции, автосохранение результатов в SYNCO/Отдел/Задача, строка «Сохранено в Google Drive» в карточке задачи.
```

---

## Этап 6 — Брейншторм и виртуальный офис (≈2 недели)

```
Этап 6.
1) Брейншторм по docs/design/SYNCO Brainstorm.dc.html: сессии с таймером, стена идей в реальном времени, по окончании — идеи в Синк.
2) Виртуальный офис по docs/design/SYNCO Office.dc.html: комнаты, статусы и присутствие через Supabase Realtime Presence, «Постучать». Встречи — по внешней ссылке (Google Meet / Zoom) у каждой комнаты: «Присоединиться ↗» открывает ссылку в новой вкладке. Встроенные звонки и Протоколист НЕ делать — они в docs/BACKLOG.md.
```

---

## Перед открытым запуском
```
Подготовь продукт к публичному запуску: страница политики конфиденциальности и условий, cookie-баннер, удаление аккаунта и экспорт данных (GDPR), лендинг с «Запросить доступ», Sentry для ошибок, PostHog для аналитики, лимиты на AI-запросы, резервное копирование базы. Составь чек-лист.
```
Затем подключите свой домен в Vercel (Settings → Domains).
